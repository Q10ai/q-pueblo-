# Q Pueblo v2 — KOS Production Contract

**State:** implemented deterministic reference candidate, no autonomous publication, no live verified retrieval, no private Q access.
**Pipeline:** Input → source/provenance gate → **Breakdown** (crosswalks, planes, memory/ability context) → **Linear** (readable cited story) → **Production** (useful contextual outputs).

## Production is an output factory, not a third truth authority

Use one immutable subject identity, claim ledger and source-version set for all derived products. If the breakdown loses source support, every affected product must be marked for recheck rather than left as current. The caller must request products through an allowlisted production contract. Production never performs hidden web retrieval or recasts legacy Q Pueblo text as original evidence.

### Input contract

Request: subject, scope, time, intended reader, required product classes, source/claim identities, optional official and historical examples, authorized public resources, source-backed option candidates, rights/consent classifications, output privacy class, limits.

Source context: exact document issuer, URL, issued/event/retrieved/checked dates, fingerprint/version, claim locator, independence, conflicts and TTL. **Old research is allowed as a retrieval lead** but does not become evidence merely because the prior report said something.

Models and harnesses: bounded breakdown graph, temporal memory, cross-plane checks, event/shock lens, issue/entity/finance crosswalks, options/RX comparison, cited narrative, leakage gate, synthetic regression tests, integrity fingerprints, reviewer/rollback receipts. All of these are backend components. No blank forms, dozens of unexplained controls or internal operational details on the website.

### Production output portfolio

1. **Primary complete paper**: continuous educational story, original-source citations, real effects and deep available context. The currently implemented linear module provides only a provisional cited sequence, not a polished source-checked full paper.
2. **Real-life examples and case studies**, only when original sources support their subject-specific claims; omit the example otherwise.
3. **RX options and conflict resolution**: mechanism, jurisdiction, stakeholders' interests, rights constraints, voluntary processes where suitable, owner, positives, negatives, tradeoffs, risks, needs and gaps. A lawful labor action or disagreement is not itself evidence of misconduct.
4. **Possibilities, scenarios and SHOCK/backups**: mechanism, assumptions, alternate futures, secondary and third-order consequences, both benefits and harms, costs and independent backups; clearly label scenario versus an actual event.
5. **Financial and institutional forensics**: exact financial states, project owners, roles, contractors, service impacts and verifiable provenance, but only when valid data is actually present.
6. **Learning and practical results**: concise explainers, historical LL, age-appropriate lessons, five-level activities only when fully built, help/service links whose eligibility and contact details have been checked.
7. **Related outputs**: summary, timeline, mapped connections, sources, revisions, corrections and human-readable meta/provenance.

All items must be substantive. An empty output type is not a shipped product. No mandatory 40 sections, filler comparisons, invented source percentages or fabricated people.

### Full RX approach

**Understand → Verify → Crosswalk → Protect rights → Compare → Test → Human choose → Observe outcomes → Correct.**

For each meaningful RX option: legal and technical feasibility, responsible institution, documented costs where known, benefits, disadvantages, safety/rights concerns, failure modes, needed resources, material unknowns and success criteria. Neutral handling of parties and due process is mandatory. No model decides guilt, directs coercion, gives individual legal/medical determinations or represents a scenario as enacted policy. Never advocate a single solution as if conflicts had already been resolved.

### Full positive/negative/risk/needs/gaps handling

These are **analytical coverage responsibilities**, not five obligatory public headings. A paper discusses them naturally where evidence supports them. The option table is generated only when substantive records exist and source-backed grounding claims are present. Private data and unresolved source conflicts block publication.

### Output meta and provenance

Every product must include: product schema and class, canonical subject ID, as-of, revision, deterministic content fingerprint, source and claim IDs, review state, source-check boundary and human publication state. The public package contains only selected source records and draft products. Internal memory pointers, risk coefficients, model prompts, authority controls, protected Q process details, credentials, private connectors, tenants and secret-bearing payloads are **not serialized**.

Provenance is not a marketing badge: \`SOURCE_LEDGER_DECLARED\` means the supplied ledger claimed the source was checked. It does **not** mean independent verification happened. Public release needs an accountable editor to inspect the exact originals and approve that edition.

### Private builds and optional deeper access

Normal users must **not** have to contact anyone for full public-domain contextual research, working source links or accessible explanations.

A requester may voluntarily seek tailored depth, regulated/private records processing, custom scenarios, additional products or institutional integrations in a **separate authenticated, consented channel**. Never imply public users have access to proprietary Q10 components or other people's records; never advertise a direct route to restricted Q internals. Do not collect confidential documents in an unauthenticated public form. No public self-service privilege escalation.

### Verified versus incomplete

Deterministic production output, metadata contracts and synthetic regression tests can be implemented without a live provider. Full source retrieval, independent corroboration, genuine real-world examples for every subject, usable secure private inquiries, advanced forensic models, original-paper composition and human approval workflows remain separate validation/deployment gates.

The old static website remains available; the clean rebuild is on a separate, nonproduction branch.
