# KOS Twin, Shadow and Continuous Learning — v2 controlled reference

Date: 2026-11-21
Status: ARCHITECTURE + BOUNDED READ-ONLY REFERENCE MODULES; not an operating Twin Pueblo, active monitoring service, private Q10 shadow or self-learning production agent.

## Did we already cover all Twin and Shadow kinds?

**No.** The previous clean rebuild included a general `qp:method:twin` and cross-plane source-graph preparation. It had not specified comprehensive real-world twin types, the different observational/testing shadows or a governed feedback-to-amendment loop. This amendment separates those missing parts from Q's own internal system.

**KOS pipeline:**
subject/idea → source checks → Breakdown (nodes, institutions, source-linked crosswalks, planes) → candidate Twins and Shadows for relevant domains → linear context/story → provisional production output → source/reader feedback → learning candidate → contradiction/falsification checks → human amendment decision → new version / rollback.

**Public experience:** people see the best current story and, where evidence supports it, an easy comparison of what happened, what could happen and what might reduce risk. Twin/Shadow/plane terminology is optional. No user must understand it to get a complete answer.

### Twin types, not only Q's internal Twin

A Twin is a **model of a real-world system**, not proof the model is accurate. The schema includes infrastructure, water/energy, operations, governance, finance, aggregate health, education, housing/community, food/agriculture, environment, transport, digital/cyber, economy/workforce, and history/futures. Its scope can include past conditions, the most recent source-backed state, and explicitly hypothetical alternatives. Never call a forecast observed history.

Some candidate Twins will have only sparse evidence. Others may eventually link licensed external simulation, GIS, utility, financial, public-health or engineering models after specific authorization, procurement, privacy review and calibration. No external model is currently invoked by these modules.

### Shadow families, not human cloning

Shadows are **non-executing comparison and observation tracks**. Public eligible kinds include observation, baseline/comparator, counterfactual, failure/risk, bounded defensive cyber/adversarial testing, data quality, governance/policy, fiscal, ecological, aggregate community impact, licensed model comparator and historical version. These are not always digital twins; e.g., a historical shadow can compare two dated snapshots without simulating a living city.

A Human Functional Shadow exists as a separately controlled Q10 concept. It is **not public eligible here**, does not impersonate someone, grants no identity or decision authority and requires explicit separate consent/security governance if ever developed in an authorized private environment. The public v2 module excludes individual/patient/child/household replicas regardless of user-submitted metadata.

### State, memory and crosswalk

Each modeled candidate references exact canonical subject, linked node/edge, admitted claim IDs and admitted source IDs, plus a date, type, bounded status and declared limitations. It may project into the applicable physical, economic, social, biological, informational, security, temporal or possibility planes while remaining subordinate to the one canonical identity graph.

No model result adds its own facts to the KOS source ledger. A simulated result is not a verified observation and cannot itself confirm the assumptions used to generate it. Multiple models agreeing does not count as independent source evidence. External software and its outputs require licensing and data-use review.

### Ongoing testing and governed learning

Continuous learning means **continuous intake and challenge, not autonomous changes to truth**:
- Recheck original source versions, new agency reports, claims and dates (TTL).
- Compare public-reported changes and observed outcomes to prior projections or human decisions.
- Log conflicts, corrections, failed branches, source gaps, reader challenges and defensive red-team findings.
- Preserve both successful and rejected alternatives in LL; no silent deletion or rewritten history.
- Compare candidate amendments against contradicting claims, alternatives, adversarial examples, privacy, reliability and rights constraints.
- Require named human admission/approval of changes; recompile derived papers, learning material and maps after an accepted correction.
- Use bounded compute, resource and attention budgets; stop recursive analysis if uncertainty or cost rises without evidentiary value.

New `compileTwinShadow` and `stageLearning` modules only **prepare internal review candidates**. They do not autonomously retrieve official information, run live simulations, update the source graph, deploy a model or publish a new story.

### Lessons from Q10 lineage without exposing private internals

Q10's controlled references separately discuss SUPRA multi-plane constraints, a human-functional shadow that cannot impersonate or authorize, search-planner shadow tests with no action path, external Twin Pueblo model/reference catalogues, and the Critical Reasoning & Learning Plane's human amendment gate. This public code exports only generic, safe vocabularies and guards, not private Q10 abilities, model recipes, provider credentials or confidential records.

### Acceptance

No public personal shadows, sensitive populations inferred from browsing, unstated live monitoring, causal claims from correlation, false forecasts, emergency notices from scenarios, model-self-certified accuracy, automatic human profiling, autonomous learning promotion or unauthorized publication. Preserve old research as contextual leads. Retain source versions, dates, hashes, corrections and the distinction between modeled states and reality.
