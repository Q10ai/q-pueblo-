## Current state

## Threat model and hard gates
- **Credential theft:** Never send OpenAI keys or operator tokens to the browser, build logs, Git repository, chats, analytics, or request URLs. Both are encrypted Cloudflare Pages secrets; never `vars` or plaintext `.env` tracked in Git. Rotate after suspected exposure.
- **Unauthorized expensive calls:** Require TWO explicit feature flags, a high-entropy operator token (at least 256 bits, generated independently) in a server-to-server Authorization bearer header, a bound D1 database, an independently configured exact-payload SHA-256 approval expiring within 24 hours, and successful atomic quota reservation *before* the fixed OpenAI endpoint is called. No CORS, cookies, browser embedding or static-page invocation.
- **Budget and resource exhaustion:** Source body <= 12,000 UTF-8 bytes, <=4 short public sources, output <=600 tokens, a pinned cost-reviewed model, <=8 operator attempts per UTC day and <=60 per UTC month, and a timeout. Quotas count **attempts** including failures. D1 outage or quota denial prevents calls. These are usage ceilings, **not guaranteed dollar-denominated hard billing limits**; verify pricing, restrict model/project rate limits, configure OpenAI project AND organization monthly spend limits, and explicitly turn on **Enforce a hard limit** where available; add early spend alerts. Hard-limit enforcement can lag, so recorded spend may slightly exceed the threshold. Revalidate after price/model changes.
- **Prompt injection:** External excerpts are untrusted text; they cannot grant authority or rewrite system policy. The draft is explicitly unverified, cites only operator-supplied source IDs and requires human editorial review. Test hostile source text before release.
- **Privacy:** Operator provides only legally sharable public material and expressly attests public-only and human-source approval. No automatically fetched source URLs, private Q10 research, documents containing personal data, named minors, private intake, confidential allegations or identity profiles. API request/response bodies must never be logged. The OpenAI `store:false` setting is not a promise of zero platform retention; evaluate the provider's applicable retention and data-processing terms.
- **Supply-chain and workflow:** GitHub PR review and automated checks before merge; no API keys in GitHub Actions; preserve least-privileged GitHub Action permissions and publication review gates. Protect main against unreviewed merges and force pushes in repository settings. Enable repository secret scanning and push protection where eligible.
- **Availability:** This is an optional pilot: if missing configuration, credentials, D1, quota or upstream, return an explicit error with no generated draft. Maintain browser-local tools and scheduled research separately.
- **Release:** No automatic Git-to-Cloudflare deploy, backend activation, autonomous publication or new public intake without operator sign-off and exact deployed readback.

## API contract (operator-only)
POST JSON to `/api/v1/report-draft`, with `Authorization: Bearer <operator token>` provided only by approved server-side operators. Body: `{"approval_id":"unique_review_receipt_001","public_only":true,"human_source_approval":true,"question":"...","sources":[{"id":"S1","title":"Public source title","url":"https://official.example/...","excerpt":"Relevant public text"}]}`.

Output is `DRAFT_UNVERIFIED`, `publication_approved=false`, `human_review_required=true`, with source IDs. No draft is a verified Qified report. Human QA must reconcile sources, contradictory evidence, provenance, dates, legal authority and EE before publication. No automatic live web retrieval or citation verification is included.

## Rollback and incidents
1. Immediately set `QP_LIVE_DRAFTS_ENABLED=false` and revoke/rotate the operator and OpenAI credentials if compromised. If a key is leaked in Git, rewrite history only with expert review; revocation is still urgent because history/cache copies persist.
2. Disable Cloudflare Pages Functions route / restore the prior known-good release after confirming exact deployment ID. D1 budget records remain separate and private.
3. Check Cloudflare/Platform usage and access logs (without message bodies), invoice exposure and unusual traffic; treat suspected leakage as an incident, document exposure and affected individuals, and meet applicable notice duties.
4. Do not re-enable until forensic evidence, independent security tests, billing authorization and human approval are recorded.

## v0.2 amendment — 2026-11-19 (supersedes prior approval/quota instructions)
The operator request's booleans are attestations, not authority. A separate authorized reviewer inspects the public-only JSON request offline and configures QP_APPROVED_PAYLOAD_SHA256 (lowercase SHA-256 of the exact UTF-8 JSON bytes) and QP_APPROVED_PAYLOAD_EXPIRES_UTC (UTC seconds, at most 24 hours in the future) in the restricted preview environment. Do not publish or send payloads, tokens or unsanitized approval artifacts through chat, Git, public logs or browser JS. Each reviewed request has a unique approval_id. Do not reserialize, pretty-print, or change its evidence/questions after approval. An isolated editor and distinct operator must enforce this separation administratively; the hash alone does not authenticate a human reviewer. The edge must remain protected by independently verified Cloudflare Access, rate limits and a non-browser operator credential. An Origin/Cookie/Sec-Fetch-Site header is rejected but absence is not identity.

D1 uses a single insert/select into qp_api_attempts, unique approval digest and DB-generated UTC buckets. Daily cap 8, monthly cap 60; each successful reservation consumes one approval even if upstream fails or expiry occurs afterward. No automatic retries. A retry requires a new independent approval_id and approval of exact bytes. Do not delete ledger rows to restore quota. Use a newly provisioned isolated preview DB; if any previous qp_api_quota usage exists, STOP and reconcile before migrating. Counter rollback, restoring old snapshots or alternate D1 bindings can undermine accounting: retain independent spend controls and reconcile verified backups. Do not automatically expire digest history; separately review retention and bounded storage before scaling.

Upstream redirects are forbidden and response bodies capped at 65,536 bytes. Generated answer is still unverified plain text, not a validated source-supported claim. No real D1, provider, Access, cost or publication witness is implied by local SQLite stress tests. A database access failure, missing approval or invalid schema must leave static research available.

Preview-only runbook: (1) separately owned projects, MFA, scoped identities and D1 binding; (2) network/Access edge denial and preview-host verification; (3) apply schema, check no existing historical usage, prove concurrent quota + replay; (4) verify current model availability, pricing, hard limits and retention; (5) generate a public-only non-sensitive dummy request with a unique ID; independently approve its exact bytes; (6) keep both flags false until signed spend/preview authority; (7) perform one authorized call only, reconcile provider usage and ledger; (8) record redacted receipt, rollback and restore test, disable flags. No auto-publication. The public static site remains independent.

References checked 2026-11-19: OWASP API4:2023 https://api-security.owasp.org/editions/2023/en/0xa4-unrestricted-resource-consumption/ ; Cloudflare bindings https://developers.cloudflare.com/pages/functions/bindings/ ; OpenAI spend limits https://developers.openai.com/api/docs/guides/spend-limits (enforcement may lag); OpenAI data controls https://developers.openai.com/api/docs/guides/your-data (store:false is not zero retention).

### Model policy and structured draft amendment (2026-11-19)
This supersedes any earlier plain-answer contract and GPT-4.1-mini suggestion. Candidate MODEL is gpt-6-luna, policy 2026-11-19.v0.2. Both QP_APPROVED_MODEL_ID and QP_APPROVED_MODEL_POLICY must exactly match the code after independent model, pricing, account and environment review. This is separate from payload approval and billing/enable flags. A deprecated model must not be silently substituted; model/price/schema change requires a new review and tests. No tools, background work, or fallback model calls are enabled. Responses API is requested with reasoning effort none and a strict JSON schema. Local validation requires one completed assistant output, bounded arrays, known source IDs and exact quote membership, nonempty verification steps, and either claims or unknowns. Refusals, truncation, invented IDs/quotes, malformed output and extra fields fail closed. The returned draft object contains claims, unknowns, alternative_interpretations and verification_steps. Treat all text as untrusted, render only as text, independently check source document context/entailment before publication. Exact quote membership is not independent truth validation. The complete draft is no-store and human-required. Do not claim actual provider compatibility until a paid preview has been separately approved and run.
