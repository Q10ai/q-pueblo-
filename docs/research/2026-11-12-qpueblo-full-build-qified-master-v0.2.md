## Executive Qified synthesis
Q-Pueblo's existing code supports a dated, source-linked civic knowledge service with static Qified reports, historical issue discovery, an evidence-first workbench, and EE/T2Y/lifecycle comparison. It does NOT yet implement a functioning multi-agency geographic digital twin, an independent automated fiscal shadow, a live source-synchronization engine, or fully reconciled election/contract data. Build the independent shadow and twin as reviewed extensions of the canonical Q-Pueblo registry. Preserve original 31 QP-00..QP-30 domains, 174 historical issue identifiers and all packet lineages. Separate what has been documented from what is advocated, presumed, announced or simulated. Use the least costly safe process and require human approval and rollback before public release.

## Product and system boundaries
Audience: general public, reporters, school/utility/infrastructure stakeholders, researchers and officials. Public questions should return the available cited answer, a dated uncertainty statement and unresolved research next steps immediately; packet research continues without hiding existing evidence.
The **Twin** maps time, place, responsibilities, jurisdictions and physical/financial facts. The **Evidence Shadow** independently traces what was announced, planned, authorized, contracted, paid, measured and disputed. The **Qified Engine** emits a dated synthesis separating primary evidence, attributed positions, analytical models and unknowns. None of these replace the responsible agencies' official records.
Audience-specific accessibility, Spanish-language and non-digital routes remain required. Don't produce individual political profiles, targeting systems or personal residence joins.

RELEASE {release_id, dated_source_hashes[], approved_by, approved_at, diff, rollback_pointer}
The source SHA is mandatory once binary/text snapshots are physically ingested; don't manufacture a hash for a URL that hasn't been downloaded.
Use OCDS-style immutable releases and compiled records as an internal model; a locally normalized record MUST NOT be labeled externally OCDS-conformant without schema validation.

## Financial "follow the money" principle
Keep exact state boundaries: estimate -> proposal -> legal authorization -> appropriation -> encumbrance/obligation -> invoice -> payment -> audited treatment -> observed service/job/asset result.
Link each amount to payer, payee (if legitimately public), fund type, date, fiscal year, contract ID, amendment/reversal, geometry if material, restrictions and original source. Reconcile pass-through funding and transfers before aggregating to eliminate double counts. An unmodified audit opinion does not certify individual transactions or broad operational quality.

## Two-sided investigative policy
Record official response, affected-entity response, independent counterevidence, and missing sources side-by-side. Equal source criteria apply to every political party, public official, company, organized group and community proponent. A reported link, contribution or procurement irregularity is not by itself a finding of corruption or intent. Where one position lacks evidence, leave it attributed and unresolved rather than falsely equating it with a verified fact.
Election datasets: official aggregate results and legally sourced committee-level finance only. No identifiable voter roll, individual ballot-return history or personal voting preference in public twin. Suppress small cells and reconstruction-by-differencing. Use precinct boundary *vintage* and exact period for geographic comparison.

## Full-stack reference implementation (NOT YET EXECUTED)
- Public static site: existing Cloudflare Pages static assets; human-approved snapshots. Reuse existing Qify and Q Tools interfaces rather than building a second one.
- Data ingestion (future): read-only source adapters for City Clerk/CivicClerk, County Clerk, State TRACER, PACOG, official GIS, County/City finance, budgets and audits. Periodic source checks only when operator-authorized. Preserve original byte/digest, TOS/license, ingestion timestamp, file version and errors.
- Storage (future): canonical Postgres/PostGIS schemas for temporal geometry, normalized entities, claims, event/fund ledger, raw immutable source receipts and editorial history. A plain relational adjacency table suffices initially; do not prematurely require a costly graph engine.
- Jobs (future): idempotent source fetch -> content diff -> extraction -> legal/privacy classification -> entity reconciliation -> claim challenge -> human moderation -> review-gated public render. Retries must not publish duplicates.
- Visualization (future): MapLibre 2D, filters by period, jurisdiction, record class and verified state; do not deploy 3D until a measured user need and licensed geometry exist.
- AI (future): retrieval-assisted summarization of citeable excerpts, abstention and contradiction reports; source-locked output generation; no automatic factual promotion, self-modifying evidence store or autonomous public action.
- Memory: append-only packet history; modification provenance; source TTL opens review and allows access to already-supported partial findings, not destructive deletion.
- EE: batch/download only when changed, cache immutable records, reuse validation, expensive models only for harder cases, use smallest model for classification where tested reliable.
- T2Y: useful sourced result, auditability, rights, reversibility, human approval and achievable cost take precedence over speculative extra compute and cosmetic twins.
- Control plane: least privilege, signed approval/release, retained rollback, corrections/redactions, public/private separation, abuse reporting and audit log.
